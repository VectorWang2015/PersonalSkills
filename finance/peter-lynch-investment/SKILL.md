# 彼得·林奇公司研究

把原书方法用于公司研究，而不是模仿作者口吻或预测市场。核心闭环是：线索只是起点，分类决定问题，公司主线必须落到盈利或资产机制，最新证据持续改变分类与持有理由。

## 先路由

只读取当前任务需要的内部能力：

| 任务状态 | 读取 |
|---|---|
| 不清楚公司应按增长、周期、修复还是资产机制研究 | [公司分类与类型迁移](references/capabilities/company-category-contract.md) |
| 从产品体验、行业观察、推荐或新闻建立公司主线 | [研究主线与反例压力测试](references/capabilities/research-thesis-pressure-test.md) |
| 检查盈利增长、利润质量、财务承受力与价格预期 | [增长、财务与估值一致性](references/capabilities/growth-valuation-consistency.md) |
| 已有持仓或旧论文，需要更新、重分类或复核退出 | [主线监测、重分类与退出](references/capabilities/thesis-monitor-exit-review.md) |
| 理由受成本价、涨跌、热门故事影响，或用户询问组合数量/配置 | [决策偏差与组合边界](references/capabilities/decision-portfolio-boundaries.md) |

只要使用当前公司或数值，先读 [当前数据契约](references/current-data-contract.md)。需要核对原书依据或合并 lineage 时再读 [证据账本](references/evidence.md)；v4 聚合发布结论见 [release-evaluation.md](references/release-evaluation.md)。

## 近邻能力边界

- 用户要合理市值、目标价、DCF、PB/PE/EV 方法选择或模型审计：优先路由 `equity-valuation-comprehensive-analysis`。本 skill 可先提供公司类型、盈利主线与风险假设，不替代完整估值。
- 银行、保险、医疗等受专门监管、会计或行业指标主导：先用相应行业 skill，再按需叠加本框架。
- 用户只要下载、解析或核对财报：先路由文档获取/解析或财务报表能力。
- 用户问指数涨跌、精确买点、技术形态或短线交易：不调用本 skill。
- 用户只问一个可直接计算的指标：直接计算并说明口径，不强制跑完整林奇流程。

## 共用硬门

1. 确认法律主体、证券代码/股类、上市地、合并范围、报告期、文档版本、币种、金额单位和分析 `as_of`。身份冲突未解决时停止精确结论。
2. 区分四栏：当前事实、管理层解释、模型/情景假设、分析判断。书中案例不能证明当前公司事实。
3. 生活经验、行业知识、朋友推荐和市场热度只产生研究线索，不是买入或卖出信号。
4. 六类是增长、盈利或资产实现机制分类，不是质量评级。高 ROE、强品牌、广渠道、低负债或现金充裕可说明质量和韧性，不能单独证明公司属于中速增长型（stalwart）。
5. 主类型先看多个可比期间的正常化收入、EPS/利润、核心业务量价与利润率，以及周期/修复/资产机制。当前核心业务和利润下降、且无充分一次性或周期证据解释时，优先考虑缓慢增长型、成熟现金牛或保持类型不确定。
6. 只有独立利润贡献、现金贡献、投入资本回报和持续性都得到验证时，才赋予当前次类型；否则写成“待验证成长选项”或“结构性模块”。重大财报、并购、资本结构、增长阶段或周期变化后重新分类。
7. 不把公司名字、业务是否“无聊”、低分析师覆盖、内部人动作或回购单独当作质量结论；解释动机、价格、材料性与反证。
8. 不使用固定 PEG 档位、13 条计分、危险项计数、持股数量、类型配比、满仓、止损禁令、固定涨跌幅或鸡尾酒会阶段生成动作。
9. 持有或退出复核基于论文是否失效、类型是否迁移、下行生存能力和同风险机会成本，不基于买入价、历史高点或短期涨跌。
10. 本 skill 不因被调用获得下单、调仓、写文件、发布或转账权限。只有用户明确要求保存时才写报告。

## 最小执行流程

按任务裁剪，不强制每次执行全部步骤：

1. **确认任务与数据。** 说明本次是分类、建立主线、预期一致性、持有复核还是偏差/组合检查。
2. **分类。** 用多期正常化增长、核心量价和周期机制选择主类型候选；把品牌、ROE、渠道和现金等质量属性另列。证据冲突时给候选、置信度和反证，允许类型不确定。未达到次类型证据门的业务只记为待验证选项或结构性模块。
3. **建立主线。** 说明为什么关注、价值如何增长、成功所需条件和一个最强反例。若公司只披露单一报告分部，把产品级资产、负债、净利润、现金贡献和投入资本回报缺口放入最强反例。
4. **核验一致性。** 将增长拆成价格、销量、份额、扩张、成本、亏损处理、并购和股本变化；检查利润质量、现金流、债务、库存和资本开支。
5. **更新状态。** 有旧论文时逐项比较新证据；没有旧论文时不要伪造买入理由。
6. **交付。** 给出证据、反方情景、缺口、下一检查点和必要的兄弟路由，不给未经授权的交易命令。

## 默认输出

普通请求使用以下结构：

- **身份与时点**：主体、证券、报告期、版本、币种/单位、价格 `as_of`；
- **分类**：主类型候选、置信度与反证；证据不足时写类型不确定。达到证据门时才写次类型，否则列待验证选项/结构性模块；质量属性单列，不参与凑标签；
- **公司主线**：价值驱动、成功条件、主要障碍；
- **一致性检查**：增长、利润质量、财务承受力、估值要求；
- **论文状态**：`成立 / 待观察 / 转弱 / 失效 / 需要重分类 / 证据不足`；
- **下一步**：最高价值验证、需要补充的数据或应转交的能力。

用户要求紧凑回答时进一步去重：身份与限制一行；结论最多三条；最强反例一条；下一期监控最多三项。同一个事实只出现一次，结论、反例和监控不得换标题重复。

展开清单、公式、组合暴露或完整证据只在任务需要时加载对应 reference。

## 停止或询问

- 证券、报告版本、期间、币种或单位无法确认；
- 关键盈利、债务、资产或损失上限无法估计，却要求精确结论；
- 任务涉及破产、重大诉讼或监管资本，需要专业复核；
- 本 skill 只给公司研究状态，不自动给交易指令；用户请求保存或发布时仍需明确授权目标和范围。
