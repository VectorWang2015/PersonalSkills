# 输入适配

## Parser输出目录

当输入是结构化财报解析目录时，按以下优先级读取：

1. `analysis_context.md`：确认原始报告、报告期、主体、主要表格路径和校验摘要。
2. `validation/validation_report.md`：记录失败和警告；失败涉及的数字标为待核实。
3. `tables_merged/*.json`：作为核心计算的首选数据源，保留表名、列名、期间、单位和页码字段。
4. `tables/*.json`：只在合并表缺少页级来源或需排查拼接错误时读取。
5. `chunks.jsonl`、`document.md`：用于业务说明、会计政策、管理层讨论和风险文本；不要从长文本中的散落数字替代主表。

可先运行：

```bash
python3 scripts/inspect_parser_output.py <解析目录>
```

脚本只建立文件清单和可用性状态，不改动输入目录。

## 原始PDF、TXT或Markdown

- 先确认文件身份、版本、页数和是否为完整报告。
- 优先调用当前环境可用的表格解析能力形成结构化数据。
- OCR错位、列头缺失、单位不明或公式无法回到原表时，停止精确计算并列出缺口。
- 年报、半年报、季度累计与单季数字不得静默混用。

## 用户粘贴数据

建立字段映射表，至少含：

| 字段 | 必填信息 |
|---|---|
| 主体 | 公司/证券、合并或母公司 |
| 时间 | 期初、期末或期间起止 |
| 计量 | 币种、元/千元/万元/百万元 |
| 科目 | 原始列名及其含义 |
| 来源 | 报表名、页码/表号或用户说明 |

缺少期初余额时，不以期末余额冒充平均余额。可以展示“按期末数的非标准近似”，但必须得到用户同意并明确标注，且不能与标准口径结果混排。

## 最小数据集

完整流程通常需要：营业收入、营业成本、净利润及归属口径、经营活动现金流量净额、销售商品/提供劳务收到的现金或等价项、扣非净利润或非经常项目、期初期末总资产/净资产/存货/贸易应收、债务与现金明细。

资本密集或杠杆任务还应提取：总购建长期资产现金支出、可识别的维护/增长项目、设计与有效产能、利用率、良率、闲置/停建、单位成本、转固后折旧与减值、已签约未支付资本承诺、担保及其他表外/或有义务、现金的受限/专项募集或专户/境外及少数股东归属/最低运营现金分层、租赁负债、未来到期表、EBIT与利息费用、已付利息现金、授信的承诺性/提款条件和历史续作信息。

应收任务还应提取账龄迁移、逾期、坏账计提、票据和保理/贴现的终止确认与追索权、期后回款。缺少任何会实质改变结论的关键项时，应影响研究状态而不是被静默忽略。

只提供部分数据时，运行可完成的模块并输出未运行模块及原因，不补造数字。
