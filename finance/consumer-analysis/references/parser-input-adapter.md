# 财报解析目录适配

仅当用户已经提供 `financial-pdf-parser` 或等价工具生成的结构化目录时读取。不要假定固定仓库路径，也不要未经请求写入 `reports/`。

## 读取顺序

1. `analysis_context.md`：报告主体、代码、报告期、来源文件、币种/单位、关键表位置和解析警告；
2. `validation/validation_report.md` 或 `.json`：失败、警告、恒等式和低置信表；
3. `tables_merged/*.json` 或 `.csv`：三表、跨页附注、非经常性损益、分部、股本等关键数字；
4. `document.json`、`chunks.jsonl` 或 `document.md`：业务、管理层讨论、风险和会计政策文字；
5. 原 PDF/发行人文件：解析冲突、缺页或更正时回查。

目录名称可以不同；按文件职责识别，不因缺少某个固定文件名就猜数据。

## 接受门

- 主体、报告期、年度/半年度/季度和全文/摘要正确；
- 原版/更正版关系明确；
- 表格标题来自正确页面和最近上方标题；
- 币种、单位、列头、期间、合并范围未错位；
- 跨页表头已合并或明确分段；
- 资产负债、现金流等关键校验已通过，或失败项被标 provisional；
- 核心数字保留页码、表号/文件名、行列与解析置信信息。

任一关键恒等式失败、单位不明、表格错位或报告身份错误时，不把数字送入公式。先修复解析或转 `financial-pdf-parser`。

## 数字与叙述分工

- 财务数字优先来自经过验证的 `tables_merged`；
- 业务描述、管理层观点和风险来自 chunks/document；
- 长文本中的孤立数字不能覆盖结构化表；
- 两者冲突时回查原 PDF 与附注，不静默选择有利数字。

## 构建证据定位

对每个关键输入记录：

| 字段 | 示例职责 |
|---|---|
| document identity | 公司、代码、报告期、版本、SHA-256 |
| source locator | PDF 页、表名/附注、列名、期间 |
| parsed locator | merged table 文件、行/列或 JSON path |
| value identity | 原值、单位、币种、符号、累计/单季 |
| validation | pass/warning/fail 与说明 |
| transformation | 单位换算、年化、平均余额、重分类或正常化 |

输出事实时引用原文件页/表和解析位置；分析判断单独标注。

## 缺失和冲突

- 没有 Q1 完整资产负债/现金流时，不推断最新库存和现金转换；
- 分部、少数股东、税、股本或并购数据缺失时，估值标 `valuation_not_ready`；
- 解析目录被移动或部分文件未交付时，列缺口并请求最小必要文件；
- 同一报告存在两个单位或列头版本时，回查原页；
- 不能访问原始解析产物时，不把研究笔记的二次数字冒充已复核原表。

## 权限

读取用户提供目录属于分析输入。下载新文件、重新解析、覆盖产物或保存报告是独立动作：只有任务要求且权限明确时执行。
