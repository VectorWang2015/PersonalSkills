# 中文研报编辑与交付

## 交付目标

让具有基本投资知识、缺少行业经验的读者理解：公司销售什么、客户为什么购买、本期哪里发生变化，以及这些变化如何影响利润、现金和价值。

采用正式、克制、具体的研究语体。先编辑论证，再排版导出。内部核查顺序和代理工作记录保留为研究依据，用户版按读者的理解顺序组织。

## 输入和范围

1. 确认目标读者、研究原稿、已落实修正、财务期间、行情日期与交付格式。
2. 复用已核数字、假设与来源。缺失或冲突的证据在相应判断处说明影响，单纯编辑不启动新一轮全量研究。
3. 保留研究原稿，新建读者版。金额、单位、期间、合并范围、盈利口径和股本范围保持可追溯。
4. 用户要求文件交付时才保存报告。普通问答可直接返回修订建议或示例。

## 相关能力

- 公司分类与业务主线参考同仓库的[peter-lynch-investment](../peter-lynch-investment/SKILL.md)，按需读取其当前数据、分类和主线能力。分类用于选择研究问题，标题与摘要无需展示完整标签体系。
- 财务矛盾交由[financial-statement-analysis](../financial-statement-analysis/SKILL.md)或对应行业入口；目标价与估值方法交由[equity-valuation-comprehensive-analysis](../equity-valuation-comprehensive-analysis/SKILL.md)。
- 仅安装本skill时，可以编辑已具备证据的报告；需要新增分类、财务或估值分析时，应取得相应能力和输入，再执行该分析。

## 编辑流程

### 1. 建立读者的理解顺序

- 公司销售什么、客户是谁 → 本期变化 → 具体原因 → 对利润、现金和价值的影响。
- 单公司使用[公司模板](templates/company.md)，综合榜单使用[Top10模板](templates/top10.md)。模板按公司问题裁剪，避免为填栏目而重复同一事实。
- 开篇约300—450字、四个自然段，依次介绍业务、本期变化、原因与关键风险。保留少量真正改变判断的数字。
- 将林奇的业务理解与成长问题融入叙述；类型、置信度和方法说明可在文后简述。多个PE与目标价集中在估值章节。

### 2. 把变量写成具体的因果过程

按[写作规范](references/editorial-style.md)展开。

- 交代谁采取什么行动，怎样改变销售、成本、交付、收款或资金需求。把“兑现、转化效率、渠道可及性”等词还原为当前情境中的动作。
- 每个重要机制充分解释一次，后文用新证据推进。相邻摘要、投资要点及正文内容重复时合并。
- 段首突出实质判断，随后给事实、比较及解释。自然段长度服从论证，避免机械切成两三句或套满高亮框。
- 正文以陈述和论证为主。删除没有实质贡献的预设反驳和防御性旁白；保留必要事实否定与真正影响判断的风险。否定词次数不作为评分标准。

### 3. 统一财务语言和证据边界

- 首次定义正文的主要利润指标，之后使用一致简称。切换到分部税前利润、归母利润或合并净利润时，就地解释比较范围。
- 正文精度服务于阅读；精确输入和核算过程放入附录。保留同比／环比、百分比／百分点、年度／半年及预测期的区别。
- 估值结论连着条件写：在盈利X和PE为Y两项假设下，对应价值Z。假设来源、股本范围与尚缺的同行证据紧邻估值说明。
- 资料缺口说明“缺什么、影响哪项判断”。复核等级、底稿路径和处理过程集中于附录；经营风险在正文解释。
- 不为填满模板补造患者数、订单、分产品利润、行业规模、概率、评分或目标价。

### 4. 审稿

逐段检查读者是否需要自行补出行业知识或因果关系。特别区分：

- 交货、确认收入与收到现金；
- 经营现金净流入与现金余额；
- 报表费用下降与实际现金成本节约；
- 已实现扣非利润与模型正常化盈利；
- 业务扩张、利润贡献与投入回报。

可按任务安排独立编辑审阅，要求给出原句、读者卡点和最小改写。模型及工具由宿主可用能力决定；无法看图时仅记录文字审阅，图像／PDF验收另行完成。编辑建议也需核对财务含义。

### 5. 排版与导出

包内提供离线导出工具，详见[安装与使用](README.md)。从技能发现结果获得本skill的真实目录，遵循宿主的Python环境约定：

```bash
python "$SKILL_DIR/scripts/export_reader_report.py" \
  --source /path/to/company_reader.md \
  --output-dir /path/to/exports \
  --title "公司名称｜研究报告" \
  --label "财务YYYYH1 · 行情YYYY-MM-DD"
```

`SKILL_DIR`指本skill目录，输出目录需事先存在。工具默认采用连续正文的[深度报告样式](templates/research_depth.css)，支持本地PNG及HTML/PDF输出，不调用模型或行情服务。

- Markdown以空行分段，写成`**结论**：正文`。残留强调标记应修正语法，不直接删除符号。
- 图表先核对数据与单位；图片使用源稿目录内的相对PNG路径，例如`![图1：收入变化](figures/revenue.png)`，工具将其内嵌并显示图题。
- 需要刻意分页时可独占一行写`<!-- pagebreak -->`。常规章节自然分页。
- 先导出到草稿目录，完成下面的验收，再将选定PDF和便携Markdown交付到用户指定位置。工具拒绝覆盖已存在的交付文件。

### 6. 实际阅读验收

1. 核对正文、图表、口径和关键公式。自动检查只证明其已检查的文本、字体和边界。
2. 按完整尺寸逐页阅读首页、最密正文、宽表和图表。缩略图用于整体检查，不能替代阅读。
3. 检查段首总结、真实中文粗体、图题／来源、表头与分页是否清楚，正文是否出现原始Markdown标记。
4. 输出验证记录中的`visual_review`默认为待人工阅读。实际完成后再记录结果，用户反馈单独保存，不把程序通过当作用户验收。
5. 交付时提供文件路径、版本与日期口径。保留先前版本，依据读者反馈迭代。

## 维护

模板、样式与脚本分离。可复现的渲染问题用最小行为测试验证，不为每份报告重新建设平台。

设计依据见[调研与取舍](references/research-notes.md)，反馈收敛和验证范围见[发布说明](references/release-notes.md)。
