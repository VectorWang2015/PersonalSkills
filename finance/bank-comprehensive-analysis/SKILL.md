# 银行综合分析

输出可追溯、可复算的银行分析，不机械复述清单。始终分开：报告原值、计算结果、估计或情景、源自原书的方法，以及截至特定日期核验的现行官方规则。

## 先确认文档身份

计算前记录：

- 法律实体、证券标识，以及集团合并或母行口径；
- 年报、中报、季报、摘要、修订或重述版本；
- 报告期间、观察日期、审计状态、币种与单位；
- 会计口径、资本并表范围、用户问题与比较对象。

实体、期间、范围或单位无法确认时，停止精确计算或缩小结论。

## 兼容财报解析目录

输入为财报解析目录时，按以下顺序读取：

1. `analysis_context.md`：来源身份、报告期间、警告和表格位置；
2. `validation/validation_report.md`：验证失败的数字保持“未核验”；
3. `tables_merged/*.json`：报表和监管指标表；
4. `chunks.jsonl` 或 `document.md`：定位净息差、贷款分类、减值、流动性、资本、客户与战略披露。

使用重要数字前回到原表或原页。不得仅因另一数字可代数反推，就把缺失的核销、风险加权资产、手续费占比或监管比率写成事实。

## 默认采用两层输出

第一层是默认交付，保持紧凑：文档身份与数据限制、经营和资产负债表主线、盈利/风险/资本各一至两个最重要发现，以及待补数据。通用的“帮我看这份季报”不自动展开所有能力。

第二层按需下钻。只有用户明确要求完整分析，或第一层发现重大异常且数据足够时，才展开阶段二资产和迁徙、完整 ECL 与拨备桥、资本稳态情景、竞争优势或估值。先说明触发原因；数据不足时列缺口，不用推断补齐。

## 只加载问题需要的能力

先用 [商业模式地图](references/capabilities/business-model-map.json) 建立最小经营地图，再按问题读取：

| 问题 | 内部能力 |
|---|---|

| 净利息收入、净息差、净利差、资产收益率和负债成本率 | [净息差分析](references/capabilities/net-interest-margin-analysis.json) |
| 不良、逾期、迁徙、核销、拨备及其他信用风险资产 | [信用风险生命周期](references/capabilities/credit-risk-lifecycle.json) |
| 收入结构、手续费、公允价值、保险总额列报、减值和拨备前利润 | [利润质量归一](references/capabilities/earnings-quality-normalization.json) |
| 核心一级资本、风险加权资产、风险加权资产收益率、分红、摊薄和增长 | [资本与增长](references/capabilities/capital-growth-analysis.json) |
| 客户、管理资产、科技、战略与持续相对优势 | [竞争优势证据链](references/capabilities/competitive-advantage-trace.json) |

涉及现行资本、风险分类、预期信用损失、贷款拨备或流动性规则时，读取 [现行标准](references/current-standards.md)，写明规则适用范围和 `as_of`。分析日期晚于核验日期时，重新检查其中的官方一手链接。

若用户问的是单个信用卡、消费贷或其他分期报价的真实成本，转交 `installment-cost-analysis`，不要运行银行财报流程。

## 不可放宽的计算规则

- 流量分子优先匹配期间平均存量分母；若只能用期末余额，明确写成近似。
- 区分百分比变化、百分点和基点。
- 不默认把单季乘四。优先使用过去十二个月；必须展示年化时，只能作为带季节性限制的敏感性情景。
- 不良余额桥的一般形式为：期初不良 + 毛新生成或转入 - 核销 - 转让/处置 - 回收/升级 ± 汇兑、并购、分类和范围变化等 = 期末不良。
- 若范围、分类或其他流量是否变化未知，`期末不良 - 期初不良 + 核销`只是不良净新增与未披露变动的平衡项；它既不是毛新生成不良，也不是毛新生成的无条件下限。只有同口径且其他流量均已知或可证明为零时，才可在明确列出假设后推导相应流量或界限。
- 不良、拨备、资本或现金流桥缺少分项时，保留“未解释项”。
- 未披露相关收入和分母时，不估算“真实手续费占比”。
- 广义不良率、减值准备/风险加权资产等非官方诊断指标不得附固定安全阈值。
- `所需风险加权资产收益率 = 选定资本充足水平 × 风险加权资产增速 / (1 - 派息率)`只用于资本充足水平恒定的简化情景。当前水平、管理层目标和适用监管要求不是同一概念。
- 原书中的历史市盈率、市净率、风险加权资产收益率、管理资产、费率和拨备数值仅是历史样例，不是当前常量。

## 输出约定

只交付用户问题和可用数据支持的部分。默认顺序为：

1. 文档身份、口径与关键数据限制；
2. 三至五条最重要结论，先给方向、驱动和反证；
3. 一张必要的核心指标表，标注 `报告值`、`计算值`、`估计值` 或 `不可得`；
4. 需要时才附深层信用、预期信用损失、资本稳态、竞争优势或估值分析；
5. 假设、反方情景、缺失输入、官方规则引用与 `as_of`。

每个重要数字都连接到报告页码、表名或解析产物位置。不得把分析转成买入、卖出、持有、仓位、杠杆、保证收益或个性化适当性建议。除非用户明确要求，不保存分析报告。

## 停止或升级

- 报告身份、单位、分母或必需流量缺失时，停止对应的精确计算。
- 文档获取、文字识别或解析失败时，转交适当的文档流程。
- 涉及银行特定第二支柱要求、未公开监管要求、重大审计争议或正式合规意见时，说明公开数据边界并建议专业复核。
- 进行当前市场估值前，取得同日股价、股本、公司行动、无风险利率和一手财务数据；否则只给方法或条件化情景。
