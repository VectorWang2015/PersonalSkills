# 版本、经验分类与维护

## V01 [原则] 维护兼容性矩阵，不宣称永久兼容

每个实际使用的环境记录 `build / platform / precision / model_scope / API_or_CLI / checked_by / evidence_level / limitation`。
`evidence_level` 至少区分文档读取、原生编译、设置读回、小段flow、保存加载和生产完成。
历史2602安装文档/API事实不证明新安装、模型组合或硬件可用；旧版本默认与新版本默认可能不同，关键参数显式固定并读回。

[案例] 一次迁移涉及VOF子步默认、prism参数和profile接口差异；这提醒检查版本默认，而不规定全部算例应固定为同一种子步模式。

## V02 [原则] 经验从候选到可复用规则

1. **收集候选**：在本地受限证据账记录问题、环境、症状、输入/源、采取动作、实际回执与反例。不要复制完整日志或用户图到公共技能。
2. **分类**：标记[原则]/[安装事实]/[案例]/[假设]。先有症状而无因果证据的修复经验仍是候选，不能升格为根因。
3. **检验适用域**：说明依赖几何、模型、版本、资源与授权的条件；核最小读回/对照，主动检查是否仅同时改变多项后的相关现象。
4. **提出规则**：将可迁移部分写成有前提的检查项，数字留在案例；失败/相反证据保留。不因一次“跑通”宣称普适。
5. **主管审定**：审查证据强度、隐私与边界后才升格为公共规则；授权恢复、门限、预算等个案政策不转化为新用户许可。
6. **发布维护**：按用户授权流程提交、发布、安装；记录版本、变更原因、受影响规则ID、验证层级和不支持范围。过时规则标注替代关系，不静默改写历史证据。

这是一条人工受控经验升格流程，不启动自优化、自动外审或无限验证计算。

## V03 [原则] 事件触发、增量维护

在阶段完成、出现可解释的失败/恢复、升级安装或发现规则冲突时更新经验；普通每一轮对话/每一步求解不维护技能、不重扫历史。
只读与本次变化相关的小证据，验证受影响路径。遇未决因果先登记假设和最小所需证据，不为写经验另外扩大计算。

## V04 [原则] 公共和私有证据分离

公共包只放薄入口和必要参考文本，示例使用 `<PROJECT_ROOT>`、`<STAR_EXECUTABLE>`、`<CASE_ID>`、`<RUN_LABEL>` 等通用占位符。
不带项目身份、用户名、节点/IP、私有绝对路径、密钥/许可内容、具体进程ID、完整日志、原始用户图像或算例。
本地证据映射与私有回执在发布目录之外；发布时使用明确文件白名单，不递归复制整个作者工作区。
通用API名字与有范围声明的历史产品版本可以保留，不能据此把私有工程称为公开可复现实验。
