# 源、几何、网格与原生验证

## N01 [原则] 先核源，不从文件名推断算例

- 在 `<PROJECT_ROOT>` 内新建 `<RUN_LABEL>`；检查标签、日志、停止标记是否已存在，避免盲重放。
- 记录 CAD/保存解/参数包的来源、版本、是否只读、实际保存时钟、关联宏与冻结设置；在副本上修改。
- 独立重建不能借用参考解场而仍称独立；继续计算则必须明确写继承哪个状态。
- 从 case-specific 输入重建，不混入通用模板默认域/网格；新旧宏的覆盖关系必须明确。

## N02 [原则] 几何身份与网格流程

1. 查单位、尺寸、朝向、载况、附体、闭合/水密、相交及表面分组。
2. 用几何位置、法向和用户定义确认区域与边界；不按枚举序号猜入口/出口/壁面。
3. 按区域实际绑定核查物理连续体，不盲选第一个同名或空默认连续体。
4. 在依赖边界类型生成近壁层的网格流程中，先正确设置边界类型；若已改类型，检查是否需重新划网格。
5. 检查真实体网格、壁层、过渡、自由面/尾流等关键区；记录质量、最小体积、适用壁面模型及 y+ 分布/限制。单元数接近不证明网格等价或精度。

[案例] 曾有外域误保留 wall，导致非目标近壁层与小段异常；改一个优化器能让短段通过，却不能修正边界流程本身。此经验说明应追查设置链，不宣称所有网格器都必须采用同一操作序列。

## N03 [原则] 从语法到真实流场，逐层给证据

| 层级 | 验证内容 | 不能据此声称 |
|---|---|---|
| 静态检查 | 语法、宏结构、路径与必要配置 | 原生 API 可用 |
| 原生编译 | 目标安装的类/方法/枚举解析 | 对象选择正确、已推进流场 |
| 原生设置读回 | 区域/边界身份、模型、dt/inner/相子步、精度、停止条件 | 物理已稳定 |
| 原生小段 | 实际步数/时钟、有限载荷、场/相分数、守恒及资源 | 长程稳定或数值独立 |
| 保存再加载 | 预期源时钟、模型/设置/后端语义匹配 | 任何未来阶段都可恢复 |

异常不能只打印 `ok:false` 后让外层把零退出当成功。汇总 wrapper、client、native、宏结果及工程指标；结果缺失须显式失败或未验证。

## N04 [安装事实] API/CLI 验证清单，而非可执行模板

历史 Linux 2602 / 21.02.007-R8 调查记录过 `-batch`、`-np`、`-gpgpu`、`-require-gpgpu-compatibility`，以及 `SimulationIterator.step(int)`、`StarPlot.export(...)` 等接口。
历史该安装版手册记录了检查点触发文件机制，检查并非即时，可能在完整步结束后才保存。
这些是带版本范围的调查记录；本 skill 没有在用户当前安装执行这些调用。

- 先查 `<STAR_EXECUTABLE>` 对应的实际 build、平台、精度和本地 API/手册；已有合法包装器优先，不复制其他机器的环境。
- 对所用 getter、枚举、profile 与场景字段在当前安装原生编译/读回；必要时录制最小宏。
- 显示名不一定是 FunctionName，读取实际选择的场函数；空灰图不是物理零值。
- stop-file/checkpoint 文件名、位置、完整时间步语义必须按本次配置核验，不猜名称建标记。
- 版本查询、安装检测不等于许可证签出或模块授权；复用合法环境，不输出密钥或修改全局许可证配置。

## N05 [原则] 资源与性能须同条件实测

- 明确物理核、逻辑 CPU、MPI 进程/线程分别是什么；逻辑 CPU 数不是物理核数，不猜“越多越快”。
- CPU/GPU 比较固定源、网格、状态、模型、精度、设置和采样，分别报加载、预热、推进、渲染、IO成本。
- GPU 严格兼容检查后，还须用实际后端/设备数和求解日志确认；要求 GPU 的任务不允许静默 CPU 回退冒充。
- 测峰值与余量、其他任务冲突；不为显存擅降精度、阶次、自由面分辨率或壁层。
- 短小模型上 GPU 更慢、大模型更快都可能成立；局部加速比不外推所有工况。
