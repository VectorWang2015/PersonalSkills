# STAR-CCM+ 工程自动化

把用户定义的工程问题推进为可追溯的原生算例、有限预算运行和诚实交付，而不是只生成一段“看似可跑”的宏。

## 触发与边界

- 适用：STAR-CCM+ Java 宏、CAD/已有算例检查、网格与模型配置、CPU/GPU 小段验证、托管运行、恢复、结果及媒体交付。
- 只要求代码/方案/离线分析时，只做该部分；加载本 skill 不等于获准签出许可证、SSH、求解或删除文件。
- 主要经验来自瞬态船舶自由面 CFD；非船舶、多物理场、结构或 FSI 需重新定义适用指标，不能照搬 VOF/船舶判据。
- 不自动做论文、批量外审、新方法探索、全库历史扫描或技能自优化。

## 先拿到最小任务契约（G01）

读取当前工作区约定、当前明确授权和指定小证据，而非全部历史。
记录 `<CASE_ID>`、输入身份及来源、目标量、工况/单位/坐标/自由度、验证资料、当前版本、运行责任人、允许的资源和输出根。
分别声明“可编辑”“可启动”“可恢复”“可清理”的范围；登记累计预算、单应用上限、带时区的绝对截止及停止条件。
关键物理输入不能合理确定时，列出缺项；安全地做不依赖缺项的工作，不假造用户许可。

## 阶段门（G02）

1. **定义**：冻结已确认输入与验收方法；未知项显式标注，保留原始资料。
2. **检查**：核实真实源、几何身份、边界/连续体、网格和设置；不以模板名代核验。
3. **原生小段**：在目标安装中编译/执行，读回对象与设置，验证实际时间推进、后端、场/载荷、保存再加载。
4. **托管长算**：只有权限、资源、停止/保存和有限预算都清楚才启动；用程序低开销监控。
5. **恢复或比较**：先核当前授权、设备健康与源有效性；分支和失败成本不能混账。
6. **交付**：分别说明运行是否完成、统计是否充分、数值敏感性是否支持、实验验证是否成立。

各门仅对本轮被请求的阶段适用。优先复用已有可信证据，把必要加载/设置核验并入下一已授权正常应用；不为填写检查表反复另开原生探针。用户要求先审图后求解时，稳态迭代与瞬态推进都须等审图放行。失败时保留证据并报告具体原因，不能为了通过而事后放宽门槛。

## 四种知识标签（G03）

- **[原则]**：可迁移的安全、可追溯与证据要求；仍受用户权限边界约束。
- **[安装事实]**：在注明的 build/平台/模型上查文档或实际验证过的 API/CLI；标明核验层级，不保证跨版本。
- **[案例]**：某工况、资源与授权下的设置、时间和门限，不是新项目默认值。
- **[假设]**：尚未证实的原因、周期、性能或可迁移性；附所需检验，不能当通过结论。

所有数值配置由目标任务确定；本 skill 不提供通用网格数、时间步、时长、RMS/OLS 门、核数或恢复次数。

## 结束时的短报告（G04）

- 本轮授权范围与实际完成阶段；未执行的部分明确写“未执行”。
- 实际原生退出、时钟、设置/后端、源及最终状态的证据位置。
- 目标量、场/守恒证据、敏感性与采样限制；不要把源码编译成功写成 flow 或精度成功。
- 有效恢复源、失败/重算成本、资源归还及归档状态；需要决策的最小问题。
- 展示真实关键图/小表并给数据入口；未有有效轨迹就说明没有动画。

该 skill 不附可直接启动的运行脚本，不自带许可证、私有节点配置或用户数据。发布与安装遵守目标仓库授权流程。
