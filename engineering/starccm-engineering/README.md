# starccm-engineering

面向Simcenter STAR-CCM+的工程自动化skill：从真实输入、安装版API与网格检查，到有限预算托管、可追溯恢复、科学证据与真实媒体交付。

## 使用

把整个目录（包括`references/`）复制到宿主支持的项目技能目录，例如`.dsh/skills/starccm-engineering/`或`.agents/skills/starccm-engineering/`。宿主负责发现及调用；目录存在不代表模型已经加载。此skill只提供工作指导，不附直接启动求解器的脚本，不自带许可证、节点配置或用户数据。

适合请求：
- “检查这个STAR宏与当前安装API，并准备原生核验。”
- “在已授权节点托管CFD，保留正常检查点及失败证据。”
- “从已有结果判断哪些工程结论有支持，导出真实场图。”

入口为[SKILL.md](<SKILL.md>)。只加载当前阶段所需参考模块，不逐次扫描全库。

## 维护原则

本skill来自工程实践的去标识化整理，不是供应商认证或通用CFD参数表。案例配置、统计阈值、节点权限和运行预算不能升级成所有项目的默认值。

更新由真实阶段事件触发：解决新类型故障、完成关键原生核验、发现可迁移流程缺口。先保留证据及适用条件，审定后更新；日常进度和重复成功不触发维护。科学含义或权限边界变化需明确记录版本与影响，不能改写旧实验结果。

## 检查

运行`python3 tests/check_package.py`检查入口、引用及行为检查案例的包结构。行为场景见[tests/behavior-cases.md](<tests/behavior-cases.md>)；这些用于审阅，不宣称已自动验证LLM行为或CFD物理正确性。
