# 阶段 1.5 — 候选四维验证

> 文件名因兼容旧引用而保留；本阶段不再执行“全部通过 V1/V2/V3”的三重验证。

## 目标

判断候选是否忠实、能否被操作化、是否有可信的增益假设，以及边界能否被真实案例证伪。验证结果是 promotion gate 的输入，不等于自动生成一个独立 skill。

## 维度 1：来源忠实度

检查：

- claim 的 `explicit / synthesized / inferred` 标签是否与证据相符；
- 关键措辞能否由列出的精确锚点支持；
- 引用是否断章取义，是否混入译者、编者或案例人物的立场；
- 是否保留作者的限定词、前提、反例和不确定性；
- 综合结论是否覆盖了所有必要来源，而不是只挑支持段落；
- 当前来源是否足以承载结论，还是需要外部事实验证。

来源忠实度存在实质性失败时，候选不能晋升。处理方式是修正 claim、补读来源、降级为推断，或淘汰；不能靠更漂亮的执行步骤掩盖误引。

## 维度 2：可执行契约

候选至少应能形成以下契约，否则更适合作为支持材料：

| 契约项 | 要回答的问题 |
|---|---|
| trigger | 哪种用户目标或任务状态应触发？哪些表面相似场景不触发？ |
| required inputs | 执行前必须知道什么；缺失时能否获取或应先询问？ |
| procedure | 有哪些决定会被该方法改变？步骤是硬性顺序还是可调整原则？ |
| output | 交付物或决策状态是什么，如何判断完成？ |
| stop/escalate | 何时停止、拒绝、请求授权、补充数据或转交其他方法？ |
| failure signals | 哪些可观察现象说明方法用错、输入不足或结果不可靠？ |

不要为了“可执行”把开放式思想伪造成机械清单。可以保留判断空间，但必须说明判断依据和产出契约。

## 维度 3：实际增益

候选的价值假设应落到真实任务行为，而不是“看起来有洞见”。先提出最小可检验假设：

- 相比 no-skill，预计改善什么：正确性、遗漏率、决策结构、可复现性、风险识别、速度或沟通质量？
- 哪类任务最可能受益，哪类任务不会受益？
- 观察到什么结果会推翻“值得做成 skill”的判断？
- 是否能用一个小型 pilot 任务验证，而不先投入完整包装？

阶段 1.5 可以用少量 dev case 做初筛，但最终增益由阶段 4 的独立评测确认。只有在加载候选方法后产生可归因的行为改善，才算增益；复述作者术语、增加篇幅或改变语气不算。

## 维度 4：边界可证伪

边界必须具体到能够设计反例或测试：

- 哪个输入条件不成立时方法失效？
- 什么规模、期限、领域、制度或风险条件会改变结论？
- 哪种兄弟 skill 更适合处理相邻任务？
- 哪个失败信号出现后应停止继续套用？
- 什么观察结果会证明作者的机制解释不适用于当前任务？

“仅供参考”“视情况而定”“不要盲目使用”不是可证伪边界。边界也不能只写成法律免责声明；它应改变路由或执行。

## 辅助信号，不是硬门槛

### 多处重复

多个独立来源位置可能提高“这是稳定主张”的信心，但要先排除同一案例的转述、章节摘要重复和 extractor 重复。同样，一次出现但描述完整的公式、协议或决策规则也可能足够强。

### 独特性

独特术语或反直觉观点可能增加信息量，但“别人也会说”不代表没有价值。常见原则若被来源明确限定并转成可靠契约，仍可能显著改善执行。反之，独特但不可执行、无增益或来源不实的观点不应晋升。

可以把重复度和独特性记录为 `signals`，不得把它们伪装成来源忠实度或实际增益。

## 验证记录

```yaml
candidate_id: pca-en-2005.fw.talk05.p231.inversion
source_fidelity:
  status: pass                 # pass | revise | fail
  evidence_checked:
    - "pca-en-2005: Talk 5 > §3 > p.231 > para.2"
  notes: "综合措辞已标为 synthesized；保留作者的适用限定"
execution_contract:
  status: plausible            # plausible | support-only | revise
  trigger: "用户只做正向论证且需要审查重大决策"
  required_inputs: ["目标", "不可接受结果", "主要约束"]
  output: "失败路径及对应规避动作"
  stop_or_escalate: "无法识别后果或决策风险很低时不启用"
actual_gain:
  status: hypothesis           # hypothesis | observed | unsupported
  expected_delta: "减少单向论证遗漏的关键失败路径"
  dev_probe: "与 no-skill 比较是否识别出预埋的反向风险"
  falsifier: "输出只改写问题，未发现额外风险或改变决策"
falsifiable_boundary:
  status: pass
  counter_cases:
    - "纯事实检索"
    - "已经完成双向风险审查的低影响选择"
signals:
  repeated_across_source: medium
  distinctiveness: medium
open_issues: []
recommended_disposition: promotion-review
```

## 结果状态

- `promotion-review`：来源忠实，契约和增益假设足以进入 promotion gate；
- `revise`：有修复路径，例如补锚点、缩窄 claim、补充停止条件；
- `support-only`：忠实但不构成独立执行契约，可作为案例、术语、边界或参考材料；
- `defer`：当前来源或评测资源不足，保留候选和缺口；
- `reject`：误引、无法修正、没有行为价值，或会造成不可接受风险。

不要用固定通过率或固定数量判断本阶段质量。逐条记录证据和失败原因，并把组合/拆分决策留给 `03b-stage1.6-promotion-gate.md`。
