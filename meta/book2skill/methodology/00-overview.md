# book2skill 方法论总览

book2skill 的目标不是把一本书压缩成更多文字，而是把其中可迁移的方法转成一组可路由、可执行、可验证、可维护的 skills。最终产物应在真实任务中比“不加载 skill”更有帮助，同时不把作者的判断、时代背景或案例相关性冒充成普遍事实。

## 渐进披露：只读当前任务需要的文件

不要默认一次加载全部方法论文档。按工作阶段读取：

| 当前任务 | 应读取 |
|---|---|
| 建立来源地图与全书模型 | `01-stage0-adler.md` |
| 选择提取角色、分块或并发 | `02-stage1-parallel-extract.md`，以及实际启用的 extractor |
| 审核候选的证据与可执行性 | `03-stage1.5-triple-verify.md` |
| 决定独立 skill、合并、支持材料或淘汰 | `03b-stage1.6-promotion-gate.md` |
| 构造具体 skill | `04-stage2-ria-plus.md` |
| 组织多个 skills、设计兄弟路由 | `05-stage3-zettelkasten.md` |
| 行为评测 | `06-stage4-pressure-test.md` |
| 打包与交付 | `07-stage5-deliver.md` |
| 重新蒸馏并与旧 skill 合并 | **先读** `08-redistill-and-merge.md`，再按它指定的盲态流程调用其他阶段 |
| 产物会影响财务分析或金融决策 | 在相应阶段额外读取 `09-financial-quality-gates.md` |

方法论文件描述的是决策标准，不要求每本书都生成相同数量的文件、相同章节结构或相同数量的 skills。

## 端到端流程

```text
原始来源
   ↓
阶段 0：来源清单、精确定位体系、全书论证地图
   ↓
阶段 1：按内容选择提取角色，自适应并发，生成可追溯候选
   ↓
阶段 1.5：来源忠实度 / 可执行契约 / 实际增益 / 可证伪边界
   ↓
Promotion gate：独立 skill / 合并 / 支持材料 / 延后 / 淘汰
   ↓
阶段 2：按渐进披露原则构造 skill 包
   ↓
阶段 3：建立必要的依赖、对比、组合和兄弟路由
   ↓
阶段 4：dev + holdout 行为评测，必要时回炉
   ↓
阶段 5：验证、版本化、交付
```

重新蒸馏不是先读旧 skill 再润色。它有一条独立支线：只向新蒸馏者提供原书和任务约束，冻结独立结果后，才允许查看旧 skill 并做对齐、匿名比较与合并。详见 `08-redistill-and-merge.md`。

## 四个核心质量维度

1. **来源忠实度**：书中明确说了什么、综合多个段落得到什么、蒸馏者又推断了什么，必须可区分；每项关键主张必须能回到准确来源位置。
2. **可执行契约**：skill 要说明何时介入、需要什么输入、执行什么动作、产出什么、何时停止、失败或权限不足时怎么办。
3. **实际增益**：价值由真实任务表现决定。至少要与 no-skill 基线比较；重蒸馏还要和旧版本匿名比较。
4. **边界可证伪**：适用与不适用条件必须能被测试或反例推翻，不能只写“视情况而定”或笼统免责声明。

“在书中多次出现”和“是否独特”只是有用信号，不是录取门槛。一次出现但定义清楚的算法可能很有价值；反复出现的常识也可能没有增益；常见原则经良好操作化后仍可能显著提升执行质量。

## 平台无关的执行原则

- 用“角色、能力、输入、输出”描述工作，不绑定某个模型、代理 API、编排器或测试框架。
- 并发量由可独立工作单元、可用执行槽、来源规模、成本与合并风险共同决定；没有并发能力时顺序执行也应得到同样的审计记录。
- 只有当确定性脚本能减少重复劳动或提高可靠性时才增加脚本；普通推理不必强行脚本化。
- 任何外部读取、写入、安装、发布或金融交易行为都继承用户原有授权边界。蒸馏工作本身不扩张权限。
- 目标平台不支持的 frontmatter 或工具功能不能成为 skill 正确运行的前提；必要信息应放在可读取的正文或支持文件中。

## 建议保留的审计轨迹

具体目录可随项目约定调整，但下列信息应能被追溯：

- 来源版本、内容摘要值、定位规则与 OCR/缺页问题；
- 原始候选、候选间合并关系及稳定 ID；
- 验证与 promotion 决策，以及对应理由；
- skill 与候选、来源之间的 lineage；
- dev/holdout 数据集版本、匿名评测结果和机械断言结果；
- 重蒸馏时的盲态冻结清单及 old/new/merged 映射；
- 未解决限制、需要人工判断的风险与发布状态。

## 不变量

1. **不凭记忆补书**：核心内容必须来自用户提供或经授权取得的原始来源。
2. **证据与推断分离**：推断可以有，但必须显式标记，不能伪装成作者原话。
3. **行为价值优先**：篇章完整、术语漂亮或作者独特都不能替代实际任务增益。
4. **保留边界**：skill 必须知道何时不用、何时停止、何时要求额外信息或专业判断。
5. **渐进披露**：入口只保留共享约束与路由；条件性细节放入按需读取的支持文件。
6. **可回滚与可比较**：不要在新版本通过评测前覆盖旧版本或丢弃来源映射。
7. **范围服从用户**：是否确认中间产物、是否批量处理、是否发布，由任务风险和用户要求决定，不设无条件的人为关卡。
