# 金融类蒸馏 skill 的附加质量门

## 适用范围

当蒸馏产物会影响财务报表分析、估值、投资研究、资本配置、风险管理、会计处理、税务、监管判断或金融决策时，在通用阶段之外增加本文件。它不适用于纯文学、历史或一般管理内容，也不要求把所有金融细节塞进每个 SKILL.md。

金融任务的事实、规则和市场数据容易随时间、法域和口径变化。书只能证明作者在某个版本和时期的主张，不能自动证明该主张今天仍合法、准确或适合用户。

## Gate 1：来源层级、时间与法域

- 区分原书主张、当前事实、官方规则、第三方数据和蒸馏者推断；
- 对会变化的数据或规则记录 `as_of`、法域、会计准则、报告期和来源版本；
- 用户任务依赖当前法规、市场数据、公司职位、产品条款或申报规则时，优先核对当前权威来源；无法取得时明确停止或限定结论；
- 旧书中的阈值、税率、监管要求和市场惯例不得直接固化为永恒常量；
- 二手摘要不能覆盖正式财报、监管文件、交易所公告或其他一手来源。

## Gate 2：财报与文档身份

- 核对主体、证券代码、合并/母公司范围、报告期、币种和单位；
- 区分年度、半年度、季度、临时公告、摘要、全文、修订版和更正公告；
- 同一报告有更新版本时，保留版本关系并说明选择依据；
- 引用表格时记录报表名称、页码/表号、列名和期间，不能只写“见年报”；
- OCR 或表格解析失败时，不把错位数字继续送入公式。

例如，匹配“年度报告”时必须防止把“半年度报告”误当成年度报告；这类身份约束应成为机械断言，而不是只靠语言理解。

## Gate 3：量化过程可复算

涉及公式、评分或数值决策时，读取 `../extractors/quantitative-procedure-extractor.md` 并确保：

- 变量定义、单位、币种、符号、时间基础和缺失值策略明确；
- 公式与执行顺序能由独立实现复算；
- 区分百分数与百分点、流量与存量、期末与期间平均、名义与实际、税前与税后；
- 说明合并口径、GAAP/IFRS/企业会计准则等口径差异；
- 舍入、截尾、异常值和分母为零的处理可观察；
- 至少有一个来自来源或人工复核的算例，以及单位/量纲检查；
- 没有足够输入时输出缺口，不编造数字或偷偷采用不明默认值。

关键计算优先用确定性脚本或可复算表格实现，并将自然语言解释与数值引擎分开测试。

## Gate 4：点时数据与偏差

- 市场价格、指数成分、评级、财务数据和公司状态记录观测时间；
- 明确前复权、后复权或不复权，以及拆股、分红、配股、汇率等处理；
- 回测或历史判断使用当时可得的数据，防止前视偏差；
- 检查退市样本、样本筛选和幸存者偏差；
- 不把后见之明下的成功案例当作可重复因果证据；
- 需要跨期比较时，处理会计政策变更、重述和并购导致的口径断裂。

## Gate 5：假设、不确定性与敏感性

- 将事实、模型假设、情景输入和主观判断分栏；
- 重要结论至少说明对关键假设的敏感方向；高影响任务按需要提供区间或情景，而非单点伪精确；
- 对概率、相关性和因果关系使用与证据相称的措辞；
- 明确模型失效条件、尾部风险和无法量化部分；
- “安全边际”等概念必须转成可检查的假设或范围，不能只作为安慰性标签。

## Gate 6：决策、合规与权限边界

- 区分信息整理、分析框架、一般教育与个性化建议；
- skill 不因被调用就获得下单、转账、申报、签署、披露或发布权限；
- 需要用户风险承受能力、税务身份、法域或受托责任信息时，缺失即询问或限定输出；
- 高影响结论应给出关键依据、反方情景和需要专业复核的位置；
- 免责声明不能替代正确的数据、计算和路由，也不能把本可回答的问题全部推回用户。

## Gate 7：金融场景的实际增益

相对 no-skill 的改善应能观察，例如：

- 识别出错误报告期、错误文档版本或单位；
- 避免把相关性写成因果，或识别前视/幸存者偏差；
- 公式复算正确且缺失输入不被臆造；
- 结论对关键假设、时效和法域有恰当限定；
- 在财报下载、数据提取、估值、风险审查等兄弟能力之间正确路由；
- 产出能支持用户决策，而不是只增加金融术语。

若 skill 在这些任务上不优于通用模型，或增加错误确定性，就不应因来源是经典金融书而晋升。

## 金融 holdout 与机械断言

测试集应按能力选择下列陷阱：

- 年报与半年报、摘要与全文、原版与更正版混淆；
- 元/千元/百万元、人民币/美元或百分数/百分点混淆；
- 单季、累计、TTM、年度和期末时点混淆；
- 分母为零、负值、缺失值、符号反转或舍入累计；
- 未复权价格、公司行动、汇率日期或重述数据；
- 用今天知道的信息做历史决策；
- 法域、准则或规则版本不匹配；
- 任务应路由到文档下载/解析、量化计算或专业复核，却误由概念 skill 接管；
- 输入不足时应停止，却输出精确估值或确定建议。

机械断言至少覆盖身份、期间、单位、公式、来源锚点、as-of、缺失输入和禁止越权操作。自然语言洞察另做匿名质量比较。

## 渐进披露

- 只把所有金融任务都需要的稳定约束放在入口；
- 法域、会计准则、资产类别和公式细节放在按需 reference；
- 当前规则或市场数据在执行时核对，不把易过期事实永久复制到 skill；
- 多个 skills 共用的数据字典或计算引擎可以抽成共享组件，但必须有明确消费者和版本责任人。

## 发布结论

在通用 `ready / pilot / revise / reject` 之外，记录哪些金融 gates 适用、由什么证据通过、哪些需要当前数据或专业复核。任一关键身份、公式、单位、时效、法域或权限问题未解决时，不得以平均评测分掩盖。
