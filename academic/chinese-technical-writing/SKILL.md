# 中文技术写作与改稿

目标是让读者按正常中文的理解顺序读懂技术论述。先确定要说明的事实和关系，再组织段落、句子与用词。正式不等于堆术语，清楚也不等于口语科普。

## 适用范围与协作

- 用于已有资料的中文起草、审读、逐句修改和全篇统一，也可局部处理摘要、方法、结论、图题及表注。
- 本 skill 处理论述和表达；技术推导、数据核验、文献检索、绘图及排版分别按任务需要使用相应能力，不自动扩成完整科研流程。
- 若只需审查防御性措辞，可使用已有的 academic-defensive-writing-auditor；若需中文句法、衔接和整篇组织，使用本 skill。领域规范另按目标文体和期刊执行。
- 不以 AI 检测分数、禁词命中率或否定词数量判断质量，也不承诺绕过检测。

## 1. 先确认本轮要做什么

从用户要求和当前上下文确定读者、文体、资料范围、交付方式；已有信息足够时直接推进，仅在影响事实或授权的关键问题上询问。

将读者定位落实为写作选择：区分读者已知的领域共识、本报告需要补足的上下文，以及读者需要据此作出的判断，再确定背景深度、定义范围、术语密度和说明口吻。面向专业读者的报告，标题通常以研究对象、方法、分析或结果组织；设问和教学式说明按实际文体选择，不把某项目的学历要求或标题偏好作为通用标准。

| 本轮要求 | 应交付 | 文件与工具动作 |
|---|---|---|
| 检查、审读，暂不修改 | 具体问题、理由和必要的局部示例 | 只读，不改文件、不编译 |
| 给整段／整节草稿，暂不写入 | 完整可读的草稿，简述重要取舍 | 不写入、不编译，不只列意见 |
| 直接修改／全篇整改 | 修改后的实际正文及简短说明 | 只改授权文件，保留可对照版本 |

最新明确指令优先。例如“暂不编译”不会因稿件是 LaTeX 而失效。用户已要求更新 PDF 等成稿时，可完成必要构建与关键页检查；单纯检查或给草稿不触发导出。

编辑前读取用户当前文件，不凭上一轮记忆覆盖手改内容。涉及已有改动、其他会话或版本时，仅处理本轮范围。提交、推送、发布和覆盖旧稿均按实际授权执行。

## 2. 先保住内容，再改善表达

快速列出本次必须保留的实质内容，不必为普通短段生成额外表格。结果类报告还应先明确必须回答哪些量或结论，供后续核对覆盖范围：

- 研究对象、目标和实际采用的方法；
- 已完成／拟开展／待验证的状态，以及阶段先后；
- 数字、单位、符号、定义、引用和比较方向；
- 判断成立所需的工况、假设、不确定性及证据范围。

语言修改保持这些内容不变。发现技术错漏时，将其作为内容修正处理并说明理由；若材料不足，指出具体缺少的依据，或收窄到现有资料能支持的表述。不要替作者补造因果、数据、验证或方法选择理由。

用户提供或确认的事实可以作为写作输入，但不能写成本 agent 已独立复现。仿真验证、数值收敛、实验对照和实船验证等不同含义应分别保留。

任务书中的禁止事项与内部核查要求，不默认逐条转写为正文。提取其对应的物理定义、适用条件或证据范围，纳入相关论述；编辑过程与执行检查另作记录。事实边界应保持，原有提醒句式可以重组。

## 3. 按读者需要组织全篇

先用一两句话明确文稿要回答的问题，再检查章节顺序。以下是可选的组织思路，不是所有文体共用的模板：

- **技术方案**：应用背景 → 当前具体问题 → 目标与阶段范围 → 方法及选择理由 → 实施工作与依赖 → 预期成果。
- **已完成研究的论文**：研究问题 → 方法 → 实际证据与结果 → 含义及适用条件；不要把真实结果改写成计划，也不要为了摘要完整而虚构结果数字。
- **技术结果汇报**：任务与主要结果 → 条件与参数定义 → 方法及校核 → 使用建议；结果和证据对应，必要推导或实现细节可置于附录。
- **设计说明／操作文档**：对象与用途 → 必要前提和接口 → 设计或操作 → 检查方法 → 异常处理与限制。

对需要独立阅读的科研报告，引言应建立研究对象、工程或科学需求、当前具体问题与本文工作的关系；已完成的工作还应交代主要结果及其用途。背景补到足以解释方法选择即可。章节顺序正确不等于动机清楚，也不必将所有文体套成“大背景—小背景”的论文引言。

每章推进一个主要问题。已有基础用来说明方案如何实施，具体计划则说明工作项、前置条件和产出。用户要求 roadmap 时，展示真实依赖和可并行工作，不以“准备—执行—验证”等抽象词代替工作项，也不编造工期或已通过的门槛。

摘要须能独立交代需求、方法和结果；结果汇报型正文可将主结论前置，二者不必采用相同顺序。用户已确认摘要结构时沿用该结构，保持摘要与正文的事实、证据强度和阶段范围一致。方法、成果、后续扩展按依赖关系展开，避免刚转向远期任务又突然返回首阶段方法；章节间用具体问题衔接，不靠反复复述摘要连接。

## 4. 逐段建立前后关系

进入新章、节时，检查读者是否已知道它解决什么具体问题、与前文有什么关系。必要时先引入动机、问题或用途，再进入公式、方法和数表；已有上下文充分时直接展开。方法章节也可用输入、输出或步骤作用建立承接，不机械追加背景段。

为当前段确定一个主要职责：交代事实、提出问题、解释原理、比较选择、安排工作或报告结果。一个段落可以有多个句子，但不同时承担几段互不相干的任务。

逐句检查：

1. 读者已经知道什么？本句接住了上一句的哪个对象或问题？
2. 本句新增什么信息？下一句是否沿着这条信息继续说明？
3. 两句是因果、转折、并列、递进、例证还是步骤关系？这种关系是否有依据？
4. 如果删掉“因此／然而／具体地”，逻辑仍成立吗？若不成立，应补足有依据的中间信息、调整顺序或分段。

连接词用于标明已有关系，不能制造关系。“具体而言”也不能修复讨论阶段、对象或尺度的突然切换。熟悉的信息通常放前，新信息随后展开；段首句本身也应能组成连贯的论述。

## 5. 逐句写清主语与动作

- 让读者知道谁采用何种方法、计算什么、据什么作判断。需要强调实施安排时，可用“本方案拟采用……获取……”。
- 常见物理事实可直接以模型、载荷、试验或数据作主语，不必每句重复“本方案／我们”。
- 将掩盖动作的名词短语还原为句子。例如把“参数获取路径的集成”写成“将各项参数代入同一运动方程”。
- 检查动词与宾语是否真正匹配，减少主谓之间的长插入和连续长定语。长句按信息关系拆分，不机械规定字数。
- 主动句常能说明工作主体，但被动表达和无主句在中文中同样可用；不以全部改主动为目标。
- 保持正式、朴素、凝练。不要把论文改成聊天、科普、营销或面向审稿人的答辩。

## 6. 选择自然且准确的词

“缺口、闭合、链路、抓手、赋能、主获取、刚体输入”等是需要结合上下文检查的信号，不是禁词表。问清它在本句究竟指什么，再选择表达：

- 公司当前存在的具体困难，可直接写“问题”；资料尚缺时，说明缺少什么。
- 数学闭合、闭环控制、接口、映射等已有明确技术含义时，正常保留。
- 需要质量与转动惯量时，写出这些量，不用笼统的“输入”替代定义。
- 专业术语前后一致，必要时首次解释。不要为避免重复，把同一概念轮换成几个近义词；也不要为了自然中文缩窄或扩大术语含义。

按实际阅读顺序检查首次出现的内部编号、对象范围、参考点和符号。无助于读者判断的内部分类移入来源记录；必要对象说明范围与用途，必要符号可用“可理解名称＋符号”，再给位置、单位或数学定义。定义须有材料依据，不凭名称猜物理身份；也不把领域常识全部展开成术语表。

对用户明确确认的用词和样段予以尊重。将其中可迁移的方法推广到其他段落，不把个人偏好或一次改稿经验说成全行业规范。

## 7. 区分科学限定与防御性旁白

对可疑句子先判断作用：删去后是否会改变结论的真实含义？

- 若它说明假设、适用范围、不确定性、未完成验证或真实风险，保留所需内容，并贴近相应判断。
- 若它主要在回应假想质疑、重复免责或解释作者为何这样改稿，删去或改成直接的事实、方法与安排。
- 对混合句，留下技术条件，移除申辩语气。一般性限制集中说明，决定当前判断成立的条件仍留在原处。

判断还应覆盖全文：同一限制是否已在变量定义、方法或适用范围中交代？当前句是在解释结果，还是在预先纠正可能的读者误解？图题优先说明对象、符号、方法和统计量；例如误差棒已定义为窗内P10–P90时，通常无需再重复否认其他统计含义。影响读图的采样、单位与比较条件仍需就地保留。

例如“科氏项不产生耗散”是技术事实；“我们并不声称补充科氏项就能解决所有问题”通常需要还原为具体模型关系。不能把“去防御”理解为删除所有否定、限制和“尚未”，也不能将其改成更强的结论。

“按用户要求”“上一版的问题”“不改回某方法”“本段不写……”属于编辑记录，不进入正文。方法选择依据需求、物理适用性和已有条件说明，不编造其他方法绝对不能做什么。

## 8. 完成一次通读与必要检查

用户以若干例子指出问题时，先归纳其反映的问题类别，再在授权范围内检查同类问题。全篇整改覆盖标题、正文、图题、表注及可编辑的图内文字；局部修改仍遵守局部授权，不因举例迁移擅自扩大范围。

先连读章、节及各段首句，检查对象、目的和叙述是否顺接；结果类报告再按写前清单核对结果节及主表是否完整回答任务，摘要和结论是否突出主要结果，比较项的单位、条件和参考点是否一致。随后通读全文，检查首次定义、指代、因果、术语、阶段安排及重复内容。图题、表注和必要附录也按同一标准处理。保留用户已确认段落，仅在一致性或实质问题确有需要时再改。

最后核对本轮涉及的事实和定义。公式、表格、引用或坐标变化可能改变文字含义，需要一起检查；编译通过、词频下降或自动检查通过均不等于文稿质量已经合格。

授权交付成稿时，使用现有环境完成必要构建和实际关键页阅读。验证只覆盖改动相关内容，不自动安装工具链、启动全量研究、逐段外审或反复要求用户确认。

## 输出约定

- 检查模式：列最值得处理的几处问题，给原句、读者会卡在哪里和建议改法；不默认长审计表或评分。
- 草稿模式：先给完整修订文本；只解释影响技术含义或组织顺序的重要改动。
- 文件修改模式：实际更新授权文件，简述关键修改、保留事项和真实检查范围，提供文件入口。
- 不将修改指令、审读对话或质量自评写进正文，不用“已彻底消除 AI 味”等无法验证的结论收尾。
