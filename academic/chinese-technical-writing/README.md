# 中文技术写作与改稿

`chinese-technical-writing` 是一个面向中文技术方案、设计说明、科研报告与论文的写作 skill。它重点处理遣词造句、主谓安排、句间承接和段落组织，也覆盖保留科学限定的防御性措辞清理。

## 核心方法

1. 先确定读者、本轮任务和交付方式，将读者定位落实为背景深度、术语密度和语体选择，区分只检查、仅给草稿和直接修改。
2. 保留事实、技术定义、证据强度和阶段安排，区分观测、估计、解释和假设试算，再调整表达。
3. 按读者理解顺序建立工作动机与论述结构；需要作出判断的分析应明确回答问题，证据取舍围绕当前用途。用明确的对象和动作说明关系，短备忘录和操作说明按用途组织。
4. 用连接词标明已有逻辑，不靠连接词制造因果。
5. 结合语境选择自然中文，不机械执行禁词表、主动句比例或句长指标。
6. 按定义、结果、适用范围或待确定事项直接组织陈述，将交接材料的事实、技术条件与内部提醒分别处理；保留科学限定，并检查共同限制在全文及图题中的重复。正式报告默认采用陈述式语体，教学等文体按用途处理设问。
7. 从用户举例归纳同类问题，在授权范围内检查标题、正文和图表文字；从用户手改稿学习信息组织和判断方式，不照搬句式或未经支持的强断言，也不扩大局部修改权限。
8. 沿实际阅读顺序核对对象、内部编号、参考点及符号的首次说明；新章、节在必要处先建立问题和前文关系，再进入公式或数表。
9. 摘要独立交代需求、方法和结果，结果汇报正文可将结论前置；按任务清单核对结果覆盖，摘要和结论突出主要结果。

主指令见 [SKILL.md](SKILL.md)，具体对照见[改写示例](references/examples.md)。

## 适用与不适用

适用于“衔接不顺”“逻辑跳跃”“英翻中”“太口语”“AI味的防御性写作”“按已确认样段统一全篇”等任务。它可以辅助起草或改稿，但不替代物理推导、数据审核、来源核验、金融分析或期刊规范。

与仓库现有入口分工：

- `academic-defensive-writing-auditor` 专注防御性写作分类及审查；本入口负责中文整体表达与逻辑。
- `drl-marine-writing-skill` 提供特定论文领域的约定；本入口不限定船舶、控制或某个期刊。
- `human-readable-equity-report` 负责中文研报的专门组织与交付；本入口可辅助句段编辑，不替代其财务口径和行业分析。

这些入口是可选协作能力，不是本包的安装依赖。只复制本目录也可完成普通文字编辑。

## 安装与调用

将整个 `chinese-technical-writing` 目录复制到宿主的 skill 发现目录，或在用户项目内建立链接，例如：

```bash
mkdir -p .agents/skills
ln -s /path/to/PersonalSkills/academic/chinese-technical-writing \
  .agents/skills/chinese-technical-writing
```

宿主也可使用 `.opencode/skills/` 或其他实际发现目录。按宿主方式重新加载技能；本包不自动修改全局配置、安装其他 skill 或调用外部模型。

调用示例：

```text
用 chinese-technical-writing 检查这段方法说明，重点看句间衔接。
只给建议，不改文件，不编译。
```

```text
按刚确认的样段重写全文，保留方法选择、公式含义和阶段范围。
直接修改指定稿件，并更新已授权的 PDF；给简短修改记录。
```

```text
给我整段草稿，我先读，不要写入文件。
```

## 文件与低成本检查

```text
SKILL.md                  主指令与模式约定
references/examples.md    按需读取的泛化改写示例
evals/cases.json           人工／agent 行为回归场景
tests/test_skill_contract.py  无外部依赖的包结构检查
```

在仓库根目录运行：

```bash
python3 -m unittest discover -s academic/chinese-technical-writing/tests -v
```

测试仅检查 frontmatter、包内链接、场景格式、关键回归场景是否保留，以及是否误带本机私有路径。它不评价句子是否自然，也不证明 agent 已遵守编辑模式。行为试读时，从场景中选取输入，让 agent 按要求作答，再按场景检查事实是否保留、是否越权、是否真正改善论述；不以术语或否定词出现次数评分。

现有26个场景。本轮新增4个：直接陈述与证据范围保留、正式报告与课堂设问的文体对照、交接材料转化为正文，以及必要技术否定和安全禁令的保留。原有22个场景全部保留，覆盖摘要与正文顺序、读者上下文、结果覆盖、分析判断、用户样段迁移及局部修改克制等。新增场景尚未执行模型行为评测，结构测试通过不改写这一状态。

## 经验来源与当前验证范围

初版总结自中文技术方案的多轮用户审读和共同改写，后续结合专业技术报告的整篇整改，补充读者定位、研究动机、结果覆盖、分析判断及用户样段迁移等指引。本轮将正式报告改稿中的经验落实为构句与通读步骤：先区分事实、技术条件和内部提醒，再直接说明结果、关系与证据范围，并按文体处理设问。具体改法由泛化示例和行为场景承接。核心经验是先组织清楚事实与判断，再处理句子；技术限定的保留与防御语气的清理需要同时完成。单次项目偏好仍应按读者与文体判断。

包内例句均为泛化构造，不包含公司、艇型、项目路径、原始数据或整段私有稿件。案例是工作方法示例，不是已完成实验的事实。尚未开展跨模型对照或独立语言质量评测；本包不宣称可量化提高写作质量或降低任何 AI 检测指标。
